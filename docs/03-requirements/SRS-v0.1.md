# ClassFlow 软件需求规格说明书（SRS V0.1）

**状态**：待评审草稿　**日期**：2026-11-26　**范围**：高中信息科技机房课堂

## 1. 引言

### 1.1 目的
确定 ClassFlow 的业务范围、用户角色、功能性和非功能性需求、接口及验收原则，作为课程设计开发、测试和变更控制依据。

### 1.2 项目背景
面向每生一台机的高中信息科技课堂，教师在课前备课并发布任务；学生在课中完成练习、按授权使用 AI 提示；教师监控作答并审核 AI 题目；系统在课后归档过程数据，支持标准化 JSON 导出。该场景与毕业设计主题保持一致，但课程设计实现范围以 P0 为核心。

### 1.3 术语
- **课时**：一次具体的教学活动，关联课程、任务及学生行为记录。
- **学习过程记录**：任务发布、提交、评价及 AI 交互等带时间戳的事件。
- **AI 草稿**：模型生成但未经过教师确认的内容，不得自动成为正式教学资料。
- **P0/P1**：必须交付的最小闭环 / 后续重要扩展。

## 2. 系统总体描述

### 2.1 参与者
- 教师：创建课程、课时、任务、监控与查询、审核 AI 内容、导出数据。
- 学生：加入课程、查看任务、提交作答、查看本人反馈、按许可使用 AI 提示。
- AI 服务：通过统一接口生成提示与题目草稿，不是拥有教学管理权限的独立用户。
- 管理维护人员：部署与运维，不纳入首轮完整管理后台开发。

### 2.2 系统边界
**系统内**：登录鉴权、课程班级、课时任务、在线作答、教师监控、过程查询、JSON 导出，以及选定的 AI 能力。

**系统外**：正式教务排课、统一学籍系统、自动评分高风险决策、家校互动、复杂教务审批、跨学校数据交换平台。

### 2.3 运行环境与约束
技术栈：Vue 3 前端、FastAPI 后端、PostgreSQL 数据库、WebSocket 课堂状态通知、统一大模型 API 接口；部署以本地或校内环境为主。

## 3. 业务流程

1. **课前**：教师创建班级与课时 → 关联知识点 → 创建任务及学习资料 → 教师审核 → 发布。
2. **课中**：学生进入课程 → 查看任务 → 提交作答 → 按许可请求 AI 提示 → 后端持久化过程记录 → 教师查询提交状态和作答。
3. **课后**：教师评价与查看班级统计 → 查询指定课时完整过程 → 导出标准化 JSON → 校验完整性与来源标记。

## 5. 非功能性需求

|ID|要求|初步验收口径|
|---|---|---|
|NFR-001|权限与隐私|后端按用户角色与资源归属校验；越权请求返回 403 或适用状态码；公开仓库不包含真实学生身份数据。|
|NFR-002|性能|目标：50 并发，95% 常用查询/操作接口 ≤800ms；记录环境、负载模型和测试工具。属于待验证目标。|
|NFR-003|可靠性|断网重连后已确认保存的数据不丢失；未确认提交不得误报成功；故障应有提示与日志。|
|NFR-004|数据互操作|学情 JSON 采用版本化 Schema，包含课时、用户匿名标识、任务、提交、时间戳和 AI 来源标记。|

## 6. 数据需求与业务实体

- `User`：用户标识、角色、状态；密码存储为安全哈希。
- `Course` / `Classroom` / `Enrollment`：课程、班级、教师和学生归属。
- `Lesson` / `KnowledgePoint`：课时与知识点。
- `Task` / `Submission`：任务、发布状态、作答内容与提交时间。
- `Feedback`：教师反馈、草稿与发布状态。
- `AIInteraction` / `AIDraft`：请求内容、AI 响应、模型来源与审核状态。
- `LearningEvent` / `ExportRecord`：业务事件、导出元数据与版本信息。

## 7. 外部接口

### 7.1 用户界面
教师端：课程管理、课时备课、任务发布、课堂看板、反馈审核、数据归档。
学生端：课程加入、任务列表、作答提交、本人反馈及 AI 提示。

### 7.2 接口
- `POST /auth/login` 登录
- `POST /courses` 创建课程
- `POST /courses/{id}/join` 加入课程
- `POST /lessons/{id}/tasks` 发布任务
- `POST /tasks/{id}/submissions` 提交作答
- `GET /lessons/{id}/progress` 查询课堂状态
- `POST /tasks/{id}/ai-hints` 获取 AI 提示
- `GET /lessons/{id}/export` 导出学情 JSON

### 7.3 实时交互与 AI
WebSocket 可用于推送提交状态；断线后通过 REST 全量查询纠偏。AI 请求必须包含授权上下文、超时与失败处理；记录模型输出来源；教师对正式发布内容拥有最终审核权。

## 8. 验收与可追踪性

每个 US/NFR 创建独立 GitHub Issue，Issue 正文包含用户故事、优先级、Given/When/Then 和负责人。实现时采用 `Issue → Branch → Commit → PR → Review → Merge → Test` 追踪链路。

最小演示闭环：教师发布任务 → 学生提交 → 教师查询 → 导出 JSON，并验证两种不同身份的访问控制。
